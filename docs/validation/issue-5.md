## Native follow-up before merge

The coordinator requested diagnosis rather than treating the timeout as harmless. Inspection of the original still-running test process showed only initial HTML, no populated focus or synchronization review control. A reproduction with denied-asset logging recorded `Denied native asset: sync-screen.js` and `Denied native asset: revision-graph.js`. The new `native-assets.test.js` failed against the original Mac allowlist. Both Mac and Android native asset allowlists omitted these modules, preventing application JavaScript initialization: this was a production regression, not merely a benchmark-completion bug. Both allowlists now serve the two modules, and the regression test checks every shipped JavaScript module against both native allowlists without executing Android runtime tests.

The benchmark also had a cleanup defect: Foundation Process starts the app in a separate process group, so killing only the launcher group left the test app running. Its launcher now records the exact child PID, and timeout cleanup terminates that child as well. The probe persists intermediate milestones and emits diagnostic state instead of leaving an empty log. Only this worktree's test processes were terminated; other workers' apps and the user's app were untouched.

After the asset fix, an isolated benchmark completed one cold and three warm Cocoa/WKWebView launches on a MacBook Pro Mac16,1, Apple M4, 16 GB, macOS 26.5.2. Interactive times were 1459.1 ms cold and 370.5, 351.5, 366.7 ms warm; populated times were 4292.7 ms cold and 370.9, 351.9, 367.1 ms warm. Every run observed zero Markdown body reads and two background confirmed-record file scans during its six-second observation window. Warm startup met the one-second target in these runs; cold startup did not. A separate overlapping run was discarded from performance evidence because another native test window occluded the benchmark during its animation-frame completion probe. The successful isolated results and exact production-file hashes are retained in [native follow-up evidence](issue-5-native-followup.json); no universal performance claim is made.

An actual isolated production Mac app (`dev.localnotes.validation.issue5`) loaded synthetic base and two fork revisions through the production file/SQLite adapter. Accessibility inspection confirmed a focused `[Conflict]` placeholder and full review entries for `Mac offline choice` and `Other offline choice`. The completed remote branch was expanded and explicitly selected; the editor value was read back before saving. The review then reported no unresolved conflicts. Filesystem assertions verified a fourth immutable resolution revision, both fork parents, the chosen description/status, and unchanged retention of all three prior revisions. The app exited and restarted with the same isolated roots; its full action list displayed `Other offline choice Completed Independent action`, Current Focus had no conflict placeholder, and sync review again reported no unresolved conflicts. This is actual Cocoa/WKWebView display/select/save/restart evidence, not a Chromium surrogate or two-device transfer test.
